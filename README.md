# bspinn — Biot–Savart-constrained coil sensitivity estimation

Joint estimation of multi-coil receive sensitivities and the image, where the sensitivities
are constrained to be **solutions of the Biot–Savart law** — either exactly (a learnable
wire-loop model) or through a **physics-informed neural network** (PINN) on the magnetic
scalar potential. Works for any number of coils, single or multiple slices, Cartesian
(fully sampled or undersampled) and non-Cartesian k-space.

```
python -m bspinn.cli fit ksp.cfl --out runs/mydata                     # any BART / fastMRI / npy dataset
python -m bspinn.cli fit ksp.cfl --traj traj.cfl --noise noise.cfl --out runs/radial
python -m bspinn.cli synthetic --coils 12 --out runs/synth            # validation with ground truth
python -m pytest tests                                                 # 62 tests, ~4 min
```

Requirements: Python ≥ 3.10, PyTorch ≥ 2.0, NumPy, matplotlib (figures), h5py (fastMRI only).
Runs on CPU (a 2-CPU laptop fits a slice in 5–20 min) or on a GPU (`device="cuda"`, optionally
CUDA graphs by default): see §8.2.

---

## 1. What exactly is constrained

**Reciprocity.** In the quasi-static regime the receive sensitivity of channel *j* is
`C_j(r) = g_j · (B_x(r) + i·h·B_y(r))`, where **B** is the field the coil would produce per unit
current, *h = ±1* is the handedness convention (sign of γ / B0 / conjugation; selected automatically),
and `g_j = a_j·e^{iθ_j}` is the channel's gain and receive-chain phase (B0 ∥ z).

**Biot–Savart ⇔ source-free Maxwell.** A field produced by currents *outside* a region Ω
(Biot–Savart with external sources) satisfies, inside Ω,
`∇·B = 0` and `∇×B = 0`; conversely every such field can be generated by external currents
(e.g. an equivalent surface current on ∂Ω). So the set of Biot–Savart solutions with the coils
outside the object is *exactly* `{ B = −∇Φ : ∇²Φ = 0 in Ω }`. This gives two implementations:

| model | how the constraint is enforced | flexibility |
|---|---|---|
| `WireLoopCoils` (hard) | each channel = closed polygonal loop(s) with learnable vertices; exact closed-form Biot–Savart per segment; penalty keeps conductors outside the object | low-dimensional, exact, robust; limited to the chosen wire topology |
| `HarmonicPINN` (soft, default) | MLP outputs Φ_j(x,y,z); B = −∇Φ via autograd (**curl-free by construction**); Laplace residual ∇²Φ (= −∇·B) penalised at collocation points | any external-source field |

The default **hybrid**: fit the wire model first, then `B = B_wires − ∇Φ_NN` with the network's
output layer initialised at zero. Training therefore *starts* at an exact Biot–Savart solution
and the network only learns the (harmonic) part the wire topology cannot explain. (A pure PINN
distilled from the wires lost accuracy in early tests; the residual formulation fixed that.)

**Variable number of coils.** The wire model owns N loop sets; the PINN shares one trunk across
coils and conditions it on a learnable per-coil latent code (auto-decoder). `HarmonicPINN.reset_coils(n)`
re-uses a trained trunk for a different array. Nothing in the pipeline assumes a coil count.

**3-D domain for 2-D data.** Collocation points are drawn from the object support and spread
through a slab (`--slab`, normalised half-thickness) around the slice(s), so the Laplace equation
is enforced in 3-D. Multi-slice stacks (`--slices`) are fitted jointly with one 3-D field per coil,
which makes the constraint much stronger.

## 1b. Complex maps, phase, and options

**The maps are complex-valued.** `maps.npy` is S×N×H×W complex64. In the default quasi-static mode
C_j(r) = e^{iθ_j}(B_x + i h B_y): each coil's phase varies over space (the angle of the transverse
field) and all inter-coil phases C_j C_k* — the information SENSE uses — are estimated. On the real
brain slice they agree with BART ESPIRiT to 7.1° (weighted mean; median 2.7°), vs 11.1° for low-res division.

*Absolute* in this README means **not normalised per pixel** (no division by RSS), not "absolute phase".
What no method can identify from the data is one phase function φ(r) common to all coils (it trades
against the image phase). `--phase-ref` fixes that convention for the exported maps; the image is
counter-rotated so C·m is unchanged, and inter-coil phases are never altered:

| `--phase-ref` | convention | notes |
|---|---|---|
| `inati` (default) | Inati et al.: all coils referenced to a virtual body coil T(r) = dᴴC(r), made real positive | weights d chosen to keep T away from zero (log-barrier on \|T\|²) |
| `inati-eig` | same with Inati's dominant-eigenvector weights | on the real brain this T nearly vanishes (min 0.0016) → a phase pole in every map; the report warns |
| `coil` | strongest coil real (ESPIRiT style) | singular where that coil is weak |
| `model` | raw Biot–Savart phase (B1⁻ transverse-field angle) | physically meaningful in the quasi-static regime |

`runs/brain8/phase_conventions.png` shows all four on the same maps. Metrics against ground truth are
computed in the model gauge before re-referencing.

**Every extension is an independent option** (defaults = the plain v1 method). Unsupported
combinations stop with an explicit message (`FitConfig.validate`):

| feature | option (default) | combines with | not with |
|---|---|---|---|
| Biot–Savart constraint | `--model pinn` (default) / `wires` (hard only) / `free` (**no physics**, Sobolev smoothness `--lambda-sobolev`) | everything | `free` × fold/shift sets |
| field relaxation | `--field-mode real` / `complex` | fit, dataset | dynamic (real only) |
| PDE strength | `--lambda-phys 0.01` (0 = soft term off, wires still hard) | all | – |
| fold / shift / free sets | `--fold-sets 0`, `--shift-sets 0`, `--free-sets 0` | fit, synthetic, `fit-dataset --mode independent` | dynamic, shared dataset; free sets need `pinn` |
| large data | `fit-dataset --mode independent|shared`, `--slice-batch 0`, `--device cpu`, `--shard`, `--pretrained` | sets (independent mode) | sets in shared mode |
| dynamic | `dynamic --rank 2 --dynamic-part both|wires|fields --max-disp-mm 0 --lambda-smooth 1e-3` | non-Cartesian, phase-ref | sets |
| phase convention | `--phase-ref inati` | all | – |
| noise whitening | `--noise` | all | – |
| coil compression | `--compress 0` (K virtual channels) | all | – |
| virtual-channel model | `--model-channels physical` / `data` | all | – |
| loop init out of plane | `--init-z-offset 0.15` (0 = in-plane) | all | – |

Physics on/off ablation (synthetic, 8 coils, same data, iterations and pipeline):

| model | subspace err | absolute err |
|---|---|---|
| `--model pinn` (Biot–Savart) | 3.1e-5 | 2.2 % |
| `--model free` (no physics, smoothness only) | 8.8e-4 | 33.6 % |
| low-res division | 1.2e-3 | 34.8 % |

## 1c. Phase singularities

There are two different kinds, and the method treats them differently.

**Reference-induced poles: avoided by construction, in the default gauge.** ESPIRiT/NLINV/Walsh
maps are defined only up to a per-pixel common phase, and fixing it with some reference R(r) puts
a vortex into *every* map wherever R vanishes (a shared pole, identical winding in all coils). Here
the common phase is fixed by the physics (each map is e^{iθ_j}(B_x + i h B_y) of one magnetostatic
field), so no per-pixel reference is involved and this kind of pole cannot occur in `--phase-ref model`. The
re-referenced exports can re-introduce one: `coil` where the reference coil is weak, `inati-eig`
where Inati's eigenvector body coil T = dᴴC vanishes. The default `inati` therefore chooses d to
maximise the geometric mean of |T|² over the object (log barrier, 8 restarts + the eigenvector
start), and falls back to the model gauge if min|T| < 0.05 anywhere. `report.json →
phase_reference.reference_strength_min_on_support` records the margin.

**Physical vortices: represented, not prevented.** A vortex of C_j = B_x + i h B_y sits where
both transverse components of that coil's field vanish (on a slice, generically isolated points).
Real coils have them, e.g. on the far side of the head from a small surface loop, and a method that forbade them
would be wrong. What the physics *does* guarantee is that each vortex is a true zero of a smooth,
source-free field (|C| → 0 there, no ±π branch cut through signal), with a winding number fixed by
the field topology. Each vortex belongs to one coil and is never shared by all of them. What it does
*not* guarantee: the fit is nonconvex, so a wrongly placed loop can put a field zero in the wrong place.

Counts (same support within a row; `report.json → phase_vortices`, `bspinn.recon.phase_vortices`):

| data | Biot–Savart (model / robust inati / coil gauge) | inati-eig | ESPIRiT | NLINV | low-res division |
|---|---|---|---|---|---|
| brain, 8 coils (v3 fit, in-plane loop init) | 0 / 0 / 0 | 1 per coil, same location (shared pole, min\|T\| 0.0016) | 26 | 3 | hundreds (noise) |
| brain, 8 coils (current defaults, `runs/brain8_zoff`) | 1, in coil 8 only (model gauge; robust inati fell back, min\|T\| 0.012) | – | 13: winding +1 in **every** coil (a shared reference pole) + extras | 3 | 223 |
| radial head, 16 coils | 9–10 in 7–8 coils / no extra / – | – | – | 12 | 10 |

The brain run shows both kinds side by side. ESPIRiT's vortices have net winding +1 in all 8 coils at the
same place, which is the reference pole. The Biot–Savart map has a single vortex in one coil, a zero of that
coil's field. Note that the robust Inati weights could not keep the body coil above 0.05 on this fit,
so the export stayed in the model gauge as designed instead of adding a pole. On the radial head the Biot–Savart vortices sit in the same coils and places as NLINV's and low-res
division's, which marks them as physical zeros of weak coils at the far side of the head. Robust inati added none. Without
the restarts it once converged to a d with a winding −1 reference.

## 1d. Virtual coils (whitening, compression)

The `real` model says every channel is e^{iθ}·(real transverse field). A *virtual* channel
v_k = Σ_j A_kj c_j (pre-whitening, SVD/GCC compression, a vendor's mode matrix) is a complex
mixture with different phases θ_j. It is still harmonic, but **not** of that form, so fitting virtual channels as
if they were coils fights the constraint. `--model-channels physical` (default) therefore models the
N physical coils and applies the known mixing A inside the data term (C_virtual = A·C_phys,
`Problem.mixC`). The cost of the fit scales with the number of virtual channels; the physics
is applied to the physical ones. The mixing is recorded automatically by `--noise` (whitening) and
`--compress K`, and the outputs are `maps.npy` (data/virtual channels, ready for SENSE on the
compressed data), `maps_physical.npy` and `channel_mixing.npy`.

| option | meaning |
|---|---|
| `--compress K` | SVD coil compression of the calibration data to K virtual channels (after whitening if `--noise`) |
| `--model-channels physical` (default) | fit physical coils, apply known mixing (exact) |
| `--model-channels data` | fit the delivered channels directly (use only when the mixing is unknown; then `--field-mode complex` or several loops per channel) |

Synthetic results (Biot–Savart ground truth, 96², noise 0.004, 800 + 800 iterations; GT error in
the data channels):

**Whitening** (12 coils, two rings, strongly correlated noise, mean |corr| 0.30; 12 → 12 channels):

| fit | GT abs err | subspace err | calib loss | rel. div |
|---|---|---|---|---|
| physical coils + known whitening matrix (default) | **15.3 %** | 7.1e-4 | 8.1e-4 | 0.012 |
| whitened channels fitted directly | 63.5 % | 4.3e-3 | 1.9e-3 | 0.029 |
| low-res division | 40.1 % | **1.6e-4** | – | – |

**Compression** (16 coils, two rings → 6 SVD channels, 97.5 % of calibration energy):

| fit | GT abs err | subspace err | calib loss | wall time* |
|---|---|---|---|---|
| all 16 physical channels, no compression | 1.1 % | 3.4e-5 | 4.2e-3 | 570 s |
| 6 virtual, physical coils + mixing (default) | **2.6 %** | **3.6e-5** | 2.3e-3 | 580 s |
| 6 virtual fitted directly, `real` field | ~100 % | 3.7e-2 | 4.1e-2 | 200 s |
| 6 virtual fitted directly, `complex` field | ~100 % | 3.2e-2 | 4.3e-2 | 300 s |
| low-res division (6 virtual) | 31.8 % | 5.4e-4 | – | – |

\*2 CPU cores, two runs in parallel. The compressed fit is not faster here because evaluating 16
physical-coil fields dominates the cost; the saving appears when the data term dominates
(many slices/frames, NUDFT). The physical maps recovered from 6 channels are only partly
identifiable (GT error 17.8 % on `maps_physical.npy`); the virtual-channel maps are what SENSE on compressed data needs.
Virtual-channel maps legitimately contain vortices (11 here versus 0 for the 16 physical maps): a mixture of
coils with different phases has zeros where the coils cancel.

In the whitening case the default gives the best absolute maps, while normalised low-res division still has the lowest
subspace error at this high SNR. With strongly correlated noise and two rings of coils the
single-loop-per-coil model is the limit there, not the mixing.

So: use virtual channels for **fitting speed** (fewer channels in the data term) but keep the
physics on the physical coils. If the mixing is unknown (e.g. vendor-combined data), `data` mode
with `--field-mode complex` is the fallback. It is much weaker on one slice (§3.1).

**Virtual conjugate coils (VCC)** are a different idea. A VCC channel is conj(c_j), which in the quasi-static
model is the same coil's field with opposite handedness (B_x − i h B_y), so it adds no new sensitivity
unknowns. It helps only where the image is real (phase-constrained/partial-Fourier recon), which is
a reconstruction choice rather than a calibration one. It is therefore not used for fitting; the fitted maps
can be conjugated for a VCC reconstruction downstream.

**Symmetry-breaking initialisation.** On a single slice, a loop initialised *in* the slice plane has zero gradient for
moving out of it (z → −z gives the same transverse field). Two-ring arrays then stayed stuck in the
plane. Loops now start alternately ±`--init-z-offset` (0.15) out of plane (thin slabs only). On the
12-coil two-ring synthetic (wires only, 600 it) this gave GT error 4.1 % → 2.7 %, subspace 6.1e-4 → 1.7e-4.

## 2. Objective

NLINV-style joint estimation, with the ad-hoc Sobolev smoothness penalty replaced by physics:

```
L = D(C, y) + λ_phys · mean(∇²Φ)² / mean|B⊥|²  + λ_norm · (log mean Σ_j|C_j|²)²  [+ wire regularisers]
```

* **Variable projection** (`varpro`, used automatically when the calibration region is fully
  sampled): the image is eliminated in closed form,
  `D = Σ_r ‖I(r)‖² − |C(r)ᴴI(r)|²/‖C(r)‖²` — the per-pixel projection residual of the coil images
  onto span{C(r)} (the ESPIRiT Eq. 20 / Walsh rank-1 residual).
* **k-space** (`kspace`, undersampled Cartesian or non-Cartesian): explicit low-res image *m*,
  `D = ‖E(m·C) − y‖²/‖y‖²` with a masked FFT or an exact separable NUDFT.

Sensitivities are **absolute** in the sense of *not RSS-normalised* (they stay complex; see §1b). This matters: RSS/ESPIRiT-normalised maps
are *not* Biot–Savart fields, so the constraint can only be imposed on the absolute maps.
In return, the classic gauge ambiguity `m → m·φ(r), C → C/φ(r)` (which NLINV/JSENSE break with
smoothness penalties) is broken by physics: φ must keep every coil's map a Biot–Savart field.
Maps are evaluated on any grid afterwards (the network is continuous); `maps_normalized.npy`
gives the usual Σ|C|² = 1 version for SENSE/BART.

## 3. Important caveats (read before trusting the maps)

1. **Single 2-D slice + `--field-mode complex` constrains almost nothing.** Any complex map can be
   written `C = (∂x + i∂y)ψ` for some complex ψ with a harmonic 3-D extension, so the PDE is
   satisfied trivially. The default `real` mode (quasi-static real field × one complex gain per
   channel) is genuinely restrictive: the in-plane field must be the transverse gradient of a real
   harmonic potential. Use `complex` only with multi-slice / 3-D data.
2. **The quasi-static assumption.** Biot–Savart ignores wave propagation and conductive loading.
   That is accurate for heads at ≤ 1.5 T and approximate at 3 T; at 7 T B1⁻ has standing-wave
   structure that is *not* a Biot–Savart field, and λ_phys should be lowered (or use `complex`
   on volumetric data). The `physics_rel_rms` metrics in `report.json` tell you how far the fit
   had to depart from the constraint.
3. **A phase common to all coils is unobservable.** Any perturbation `C_j → C_j·φ(r)` shared by
   every channel is absorbed by the image for *every* method; the physics prior assigns it to the
   image. Demonstrated in the synthetic test with a non-harmonic phase (§5).
4. **Channel mixing.** Pre-whitening and coil compression produce complex linear combinations of
   physical channels, which are *not* e^{iθ}·(real field) and so violate the `real` model. By
   default (`--model-channels physical`) the physical coils are modelled and the known mixing
   matrix is applied in the data term (§1d).
5. **Geometry matters.** Set `--plane` (where B0 points relative to the image) and
   `--pixel-spacing`/`--slice-spacing`; the PDE is not invariant to anisotropic scaling.
6. **Non-Cartesian trajectories must be exact**, including gradient-delay correction. On a
   rotationally symmetric phantom a wrong spoke ordering still grids to a plausible-looking disk;
   only the coil data reveal it. Pass the scanner/BART trajectory with `--traj`.
7. **Conductors and the air around the object (fixed in v8).** Earlier versions could produce maps
   with wire-shaped holes (after RSS normalisation) and outliers up to ~300× the median inside the
   object and ~2600× outside it (knee15). Causes: (a) the wires kept training in the PINN stage
   *without* the keep-out penalty and drifted onto the object edge (min. distance 0.003 vs margin
   0.1); (b) the keep-out only tested vertices, not the segments between them, against a random
   2048-point subsample, with a mean-over-vertices weight too small to matter; (c) a thin wire's field
   is ~1/d, and in 2-D a loop facing the object crosses the image plane in the air next to it;
   (d) the network correction had no Laplace penalty outside the object. Now: a signed distance to
   the hole-filled object (2-D: the outline extruded by ± `slab`, as the anatomy continues
   through the plane) is enforced along every segment in every stage, normalised so a violation
   outweighs the data term (`outside_margin`); conductors have a finite radius (`wire_radius`,
   Rankine core: exact beyond it, so exact inside the object); and a quarter of the Laplace
   collocation points lie in the air (`air_colloc`). Knee15 / brain8 (`quality="fast"`): max |C|
   / median inside the object 302 → 14.5 / 3.5 → 3.0, outside 2611 → 60 / 219 → 18; network
   correction in air 172 → 2.3 / 44 → 3.2 × median; ACS combine→expand residual 0.0961 → 0.0929 /
   0.0524 → 0.0541; synthetic 2-D map error unchanged (3.9e-5 → 3.75e-5). What remains above ~10×
   the median sits next to coil elements at the object edge, where the measured coil images show
   the same (knee: one coil 16× the median coil at low resolution), or in air near a conductor,
   where the data carry no information: use `mask_maps=True` if those regions matter to you.
8. **Objects cut by the FOV edge; wrap-around in the support.** The object support is estimated
   from a low-resolution, periodic image: an object touching one edge also lit up the opposite
   edge. Small disconnected components (< 20 % of the largest) are now dropped. Beyond the FOV the
   keep-out measures the distance to the visible object (conductors may sit just outside an edge the
   anatomy is cut by; `fov_extend` assumes it continues further). Close to such an edge the
   sensitivity of the nearest coil rises steeply over fewer pixels than the calibration region
   resolves; coil *shares* there agree with the data, but `|C|` (with `normalise="none"`) is an
   extrapolation: a larger `calib` constrains it (24 → 48 halved the peak on a cut-off knee).
9. **Conductors inside the FOV.** A wire crossing the image plane in the air (e.g. a tight head coil
   in a large FOV) is physical, and its field (bounded, zero on the conductor axis) is visible in
   the air there. `lambda_fov > 0` pushes conductors out of the imaged region where the data allow;
   on a 12-channel brain it cost 28 % data fit, i.e. the conductors are really inside that FOV.

## 4. Usage

### 4.0 Quick start: a k-space array in, maps out

```python
import numpy as np
from bspinn.api import estimate_maps, coil_combine

ksp = np.load("ksp.npy")          # complex; unsampled entries exactly 0

maps, info = estimate_maps(ksp, "2d", spacing=(1.0, 1.0))                            # (coils, x, y)
maps, info = estimate_maps(ksp, "3d", spacing=(1.0, 1.0, 1.0), axes="auto")         # (coils, x, y, z)
maps, info = estimate_maps(ksp, "dynamic", spacing=(1.5, 1.5), rank=2)              # (coils, x, y, time)

# maps and image together: the image is the full-resolution SENSE reconstruction with these maps
# (closed form if fully sampled, CG-SENSE otherwise; per frame for dynamic), ksp ~ F(maps * image)
maps, image, info = estimate_maps(ksp, "2d", return_image=True)
image_joint = info["image_joint"]      # the image of the joint fit itself: calibration resolution only
```

The fit is joint (maps and image, NLINV-style), but its image lives on the calibration grid: it
carries only the information of the calibration region (24² centre by default), so it is a
low-resolution image, returned interpolated to the full matrix in the same phase/scale convention as
the maps. The full-resolution `image` uses all acquired samples with the final maps. Both satisfy
`ksp ≈ F(maps · image)` (the joint one only inside the calibration region). Measured on a 64² synthetic
(8 coils, σ = 0.01, `quality="fast"`): `image` is within 3.3 % of the truth (noise level; scale 0.998)
fully sampled and 12 % at R ≈ 3; `image_joint` reproduces the calibration data to the noise floor.

`maps` has the shape and axis order of `ksp`, phase-referenced (Inati virtual body coil) and
RSS-normalised (`normalise="none"` keeps the raw, smoothly extrapolated model scale). Command line,
same options (`.npy`, `.npz` with `ksp`/`mask`/`noise`, or BART `.cfl` with `--coil-axis -1`):

```
python -m bspinn.cli maps ksp.npy --layout 2d|3d|dynamic --out maps.npy [--spacing ...] [--plane ...]
       [--axes auto|xyz] [--calib 24] [--noise noise.npy] [--quality fast] [--rank 2]
       [--physics helmholtz --b0 3] [--image img.npy] [--mask-maps [sup.npy]] [--set iters_pinn=1000 lambda_phys=0.1]
```

What matters:

* **Calibration**: the centre `calib` points per axis (default 24 in 2-D/dynamic, 12 in 3-D) should
  be (densely) sampled; set `calib` to your ACS size. Undersampled entries inside it are handled
  (k-space data term), but must be zero.
* **Geometry**: `spacing` in mm (anisotropic voxels matter: the PDE is not scale-invariant).
  Where B0 points relative to the image matters a lot: `plane="auto"` (default) tries B0 through
  the slice (`axial`), along the image rows (`coronal`) and along the columns (`coronal_t`) with
  short wire fits and keeps the best (`info["plane"]`, `info["plane_scores"]`); it picked the stated
  orientation on knee15 (coronal) and brain8 (axial). A wrong plane fitted a coronal knee 2.5× worse
  and produced false zeros inside the object. Give `plane=` to skip the search (~6 short fits).
  In 3-D `axes="auto"` does the same.
* **Undersampling masks** (`bspinn/masks.py`): `cartesian_mask(shape, R, acs, pattern)` builds
  Cartesian masks with a fully sampled calibration block: 2-D / dynamic lines (`uniform`, `random`,
  `vd` variable density; dynamic: a shifted lattice or a new draw per frame) and 3-D phase-encoding
  planes (`uniform` R1×R2, `caipi`, `vd`, `poisson` variable-density Poisson disc), with optional
  `partial_fourier` and an `extent` (never sample outside the acquired data). For uniform/CAIPI `R` is the
  lattice spacing; for the random patterns it is the net acceleration including the ACS.
  `estimate_maps(..., undersample=4)` or `undersample=dict(R=4, pattern="vd", seed=1)` (or a bool
  mask) undersamples fully sampled data retrospectively. The calibration block defaults to the fit's
  `calib`, so the fit always sees a fully sampled calibration region and uses every other acquired
  sample inside its calibration grid; `return_image=True` unfolds the rest (CG-SENSE).
  `info["mask"]`, `info["R_effective"]`. Your own mask works the same way:
  `m = cartesian_mask(...)` (or any bool array), then `estimate_maps(ksp, ..., undersample=m)` for fully
  sampled data, or `estimate_maps(ksp * m, ..., mask=m)` for data that are already undersampled. A
  warning is issued if the mask does not fully sample the central `calib` block the fit uses.
  CLI: `maps ... --undersample 4 --pattern vd`, `maps ... --undersample-mask m.npy` or
  `python -m bspinn.cli mask --shape 320 368 --R 4 --acs 24 --out mask.npy`.
  On a 15-channel knee (Biot–Savart maps fitted from the undersampled data, `quality="fast"`;
  complex NRMSE of the CG-SENSE image against the same maps' fully sampled combination):

  | pattern, net R | λ | ours, as delivered | ours, `mask_maps` | ours on ESPIRiT's support | ESPIRiT |
  |---|---|---|---|---|---|
  | uniform, 3.3 | 1e-3 | 1.17 | 0.60 | 0.80 | 0.93 |
  | uniform, 3.3 | 1e-2 | 0.53 | **0.47** | 0.58 | 0.65 |
  | vd, 4.0 | 1e-3 | 0.99 | 1.35 | 1.40 | 1.55 |
  | vd, 4.0 | 1e-2 | **0.37** | 0.54 | 0.56 | 0.59 |

  With a regular lattice a support constraint (`mask_maps=True`) helps, with random-like patterns the
  full-FOV maps do; λ = 1e-2 beats 1e-3 everywhere (also at R = 2), so it is now the default
  `sense_lambda` of `return_image`. This knee is noise-limited beyond R ≈ 3 for plain SENSE.
* **Joint image solve** (`solve_image=True`, CLI `--solve-image`; 2-D and dynamic with `rank=0`): after
  the calibration fit, maps and a full-resolution image are refined together on all acquired k-space,
  NLINV-style. Each iteration solves the image by a few warm-started CG-SENSE steps inside the acquired
  k-space extent and takes an Adam step on the maps (same physics penalty, norm and keep-out). The maps
  are RSS-normalised inside the stage, so one Tikhonov weight (`lambda_joint_img`, default 1e-2) acts
  uniformly. `joint_maps="exact"` (default) evaluates the maps at every pixel and back-propagates the
  data-term gradient in chunks; `"interp"` uses the calibration grid plus k-space interpolation (about
  40× faster, but it biases the exact field). `lambda_joint_prox` keeps the maps near the calibration
  solution. **Measured value: small; it only helps when calibration data are scarce.** Image error vs the fully sampled image, magnitude NRMSE:

  | data | calibration maps + CG-SENSE | joint, exact | joint, interp | cost (exact / calib) |
  |---|---|---|---|---|
  | synthetic 64², R_net 2.0 (map error) | 0.0787 (6.4e-5) | 0.0792 (7.3e-5) | – | 2.3× |
  | knee15, uniform R4 + ACS 24 (R_net 3.3) | 0.1763 | 0.1756 | 0.1784 | 7.6× |
  | knee15, uniform R3 + ACS 8 (R_net 2.9) | 0.1267 | **0.1209** | 0.1333 | 16× |

  With a fully sampled calibration block of normal size the physics-constrained calibration maps are
  already as good as the data allow; with a small one (8 lines) the joint fit gains ~5 %, at 16× the
  cost (the exact variant runs about 30 s per iteration at 320×368, 15 coils, one CPU core). An early version that solved the image against the raw (unnormalised) maps
  appeared to gain 11 % on the knee; that came from its spatially varying effective regularisation, and
  its own starting image was much worse (0.42). It is kept as an option for experiments and
  calibration-poor data; the benchmark was not rerun with it.
* **Image reconstruction**: `return_image=True` / `sense_image` only estimates k-space inside the
  acquired extent (first..last sampled line per axis). Zero-padded edges, partial-Fourier gaps and a
  cropped readout stay empty, as in a zero-filled reconstruction; undersampling inside the extent is
  unfolded by CG-SENSE. Earlier versions treated those edges as undersampling and filled them with
  amplified noise (high-frequency stripes; on a zero-padded knee 20 % of the image energy outside the
  acquired extent, and 3× the error at R = 2). `extrapolate=True` restores that behaviour.
* **Masked maps**: `mask_maps=True` zeros maps and images outside the estimated object support
  (`info["support"]`; tune with `support_threshold=0.1`, `support_dilate=2`), or pass your own bool
  mask (`mask_maps=sup`; CLI `--mask-maps [sup.npy]`). By default the maps cover the whole FOV, since
  the physics model extrapolates smoothly. On a 64² synthetic at R ≈ 3 the default support covered
  the whole object (72 % of the FOV), and support-constrained CG-SENSE lowered the in-object error
  from 16.2 % to 14.9 % and the energy outside the object from 1.15 to 0.65. If the mask clips the
  object edge, SENSE is zero there, so lower the threshold or dilate more.
* **Noise**: pass noise-only samples `(n, coils)` for pre-whitening if you have them; maps come back
  for the original channels (the SENSE image whitens data and maps alike). With strongly correlated
  channels use `quality="default"`: the fit converges more slowly after whitening.
* **Dynamic**: Cartesian frames, each with a sampled centre. `rank` = number of temporal modes of the
  coil motion (`rank=0`: one static map set; frames only add data). `info["temporal_modes"]` (T×rank)
  is a respiratory-like surrogate.
* **Helmholtz** (`physics="helmholtz"`, 3-D only): for body imaging at ≥ 3 T; give the real voxel
  size (it sets the wavelength) and `b0_tesla`. `info["tissue"]` = fitted homogeneous (ε_r, σ).
* **Run time** (measured, 2 CPU cores, `quality="fast"`): 2-D 48×48, 6 coils ≈ 1.5 min (300 PINN
  iterations); dynamic 48×48×16 frames, 8 coils ≈ 10 min; 3-D 32³, 12 coils with `axes="auto"` ≈ 7 min;
  3-D 48³ at evaluation settings ≈ 16 min (Laplace) or 42 min (Helmholtz) on one core. Cost scales with the calibration grid
  (`calib`), not with the image matrix. Use `device="cuda"` if available (§8.2).
* **Sanity check on synthetic data with known maps** (same calls, `quality="fast"`): subspace error
  3.75e-5 (2-D 96², 8 coils), 2.4e-4 (dynamic, moving anterior coils; the recovered temporal mode
  correlates 0.997 with the true motion), 3.9e-4 (3-D 32³; `quality="default"` at 48³ gives 5.8e-5,
  §8). `info["data_loss"]` is the relative calibration residual; compare it between runs (plane,
  options), not across datasets.

## 5. Validation

All numbers below are reproducible with the commands in `run_real.sh` / §4 (2 CPU cores).

**Synthetic, known Biot–Savart ground truth** (`python -m bspinn.cli synthetic ...`).
*Subspace error* = 1 − |⟨c_est,c_true⟩|²/(‖c_est‖²‖c_true‖²) per pixel (gauge-free);
*absolute error* = relative L2 after one global complex scale (only physics-constrained maps can be
good here, since RSS-normalised maps carry a different per-pixel gauge).

| case | method | subspace err | absolute err |
|---|---|---|---|
| 8 coils, 1 slice, fully sampled, 96² | **Biot–Savart (hybrid PINN)** | **3.1e-5** | **2.2 %** |
| | wire model only | 9.9e-4 | 4.5 % |
| | low-res division (mSENSE) | 1.2e-3 | 34.8 % |
| same + 1 rad non-harmonic phase common to all coils | Biot–Savart | 3.2e-5 | 18.4 % (unobservable common phase → image) |
| 12 coils, 3 slices jointly, R=3 random, k-space term | **Biot–Savart** | **1.2e-3** | **28 %** |
| | low-res division | 0.195 | 87 % |

Physics residual of the fitted fields: curl ≈ 1e-6 (exact by construction), relative
div = −∇²Φ: 0.003–0.004 per unit length.

**A warning about held-out k-space prediction.** It is a popular ground-truth-free score, but on
the 12-coil synthetic case the *true* maps score 0.784 NRMSE, the Biot–Savart maps 0.784, and the
(much worse) low-res division maps 0.739. Data-derived maps absorb object structure and noise and
interpolate held-out samples better while being the wrong sensitivities. `scripts/benchmark_maps.py`
implements the score (with an optional common support mask, which changes rankings a lot), but it
cannot rank map quality; read the real-data numbers below with that in mind.

**Real data** (public BART workshop data, `mrirecon/bart-workshop`):

| dataset | coils | encoding | physics rel. div / curl | held-out NRMSE (lower = closer to data) |
|---|---|---|---|---|
| brain, `ismrm2016/pics-brain` | 8 | Cartesian 2-D Poisson disc (~R 8), k-space term | 0.015 / 1.7e-6 | ESPIRiT 0.451, low-res div. 0.483, **Biot–Savart 0.490** (0.502 with in-plane loop init), BART NLINV 0.503 (common support, λ=1e-2) |
| head, `mri_together_2025` | 16 | radial, noise-whitened, exact BART trajectory + RING delay correction | 0.037 / 4.5e-5 | BART NLINV 0.348, low-res div. 0.352, **Biot–Savart 0.393**, wires only 0.420 (unmasked, λ=1e-3) |

On both, the Biot–Savart maps are smooth, noise-free, defined over the whole FOV and reproduce the
inter-coil phase structure of the data-driven maps (see `runs/*/maps_normalized.png`); SENSE images
are visually equivalent. On the brain they tie with BART's NLINV; given the metric caveat above,
the held-out numbers do not show a meaningful difference. The radial head data has a hard
consistency floor: even a free per-coil image explains only ~79 % of the calibration samples
(squared residual ≈ 0.046), so no coil model can go below that; the fit reaches 0.054. That run
used the earlier conductor standoff (0.05), which let a few loops sit at the scalp and produced
near-field streaks outside the head in the absolute maps; the default is now 0.1 (`--outside-margin`).

Practical note on non-Cartesian data: with a wrong spoke order this head still gridded to a
plausible-looking smooth disk; only per-coil data consistency (and BART's own trajectory)
revealed it. Always pass the scanner/BART trajectory.


## 6. Extensions

### 6.1 Large datasets (fastMRI)

```
# per volume: all slices jointly (one 3-D field per coil), streamed centre k-space, slice minibatches
python -m bspinn.cli fit-dataset "/data/multicoil_train/*.h5" --out maps/ --mode independent \
       --calib 48 --slice-batch 4 --device cuda --shard 0/4        # run shards 0..3 on 4 GPUs
# amortised: one trunk for all volumes, per-volume/per-coil latent codes, held-out prior test
python -m bspinn.cli fit-dataset "/data/multicoil_train/*.h5" --out shared/ --mode shared \
       --steps 20000 --holdout 20 --slice-batch 4 --device cuda
python -m bspinn.cli fit new_volume.h5 ... --pretrained shared/trunk.pt    # start new fits from the trunk
```

* `fastmri.load_fastmri` reads only the central `calib`×`calib` k-space of each slice from the
  `.h5` (a 1 GB knee volume costs a few MB), takes pixel spacing / slice thickness from the
  ISMRMRD header and the B0 orientation from the `acquisition` attribute (`AX*`, `COR*`, `SAG*`).
  Maps are exported at full resolution from the continuous model (`maps.npy`, S×N×H×W).
* Coil counts may differ between volumes in both modes.
* `--device cuda` moves the calibration problem, models and full-resolution map evaluation to the GPU
  (§8.2). (Developed on a CPU-only machine: run `scripts/bench_gpu.py` once to check your GPU.)
* Cost on CPU (1 thread): ~0.1 s per wire iteration and ~0.3 s per PINN iteration for a
  3-slice minibatch at calib 32 → a few minutes per volume. A full fastMRI training set
  (thousands of volumes) is a GPU / multi-worker job; `--shard i/n` splits the file list.
* Real fastMRI data is licence-gated and was not available here; everything was tested on
  files written in the exact fastMRI format (`fastmri.write_fake_fastmri`, with ground truth).

### 6.2 Non-resolvable components (ENLIVE-style multiple map sets)

ENLIVE adds free sets I(r) = Σ_s C⁽ˢ⁾(r) m_s(r). For the physical causes of such components the extra
set is **the same coil field at displaced coordinates** — a much stronger constraint:

| option | extra sets | cause |
|---|---|---|
| `--fold-sets 1 --fold-axis col` | C(r ± FOV) along the phase-encode axis (fixed) | object larger than the FOV |
| `--shift-sets K` | C(r + t_s), t_s learnable | motion between samples, fat/chemical shift |
| `--free-sets K` | independent Biot–Savart fields | anything else (direct ENLIVE analogue) |

Displaced copies are masked to zero within `--outside-margin` of the (learned) coil conductors —
the object cannot overlap the coils, and without this the near-singular field next to a conductor
absorbs noise. Unneeded sets are suppressed with ENLIVE's factor-norm idea: a per-pixel ridge on
each extra set's *contribution* ‖C⁽ˢ⁾m_s‖² (`--set-ridge`, scale-invariant) and ‖C⁽ˢ⁾‖² for free
sets (`--lambda-sets`). VarPro solves a K×K system per pixel. Outputs `set_images.npy/png`.

### 6.3 Dynamic MRI: low-rank, every frame Biot–Savart

```
python -m bspinn.cli dynamic ksp.cfl --traj traj.cfl --spokes-per-frame 21 --rank 2 --out runs/dyn
python -m bspinn.cli dynamic --synthetic --rank 2 --out runs/dyn_synth          # moving-coil ground truth
python -m bspinn.cli dynamic ksp.cfl --traj traj.cfl --dynamic-part wires --max-disp-mm 15 ...   # most constrained
```

C_j(r,t) = e^{iθ_j}(B_x + i h B_y) with

B_j(r,t) = B_wires(r; v₀ + Σ_k a_tk V_k) − ∇Φ_j^static − Σ_k a_tk ∇Φ_jk

* wire part: exact Biot–Savart for **every frame**, with low-rank conductor motion (a flexible
  array moving with the chest);
* PINN part: a real rank-K combination of harmonic potentials → harmonic for every frame
  (Laplace is linear), so the constraint needs no per-frame enforcement;
* θ_j constant in time; temporal modes a_t initialised from the data (PCA of the per-frame
  coil-energy distribution, a self-gating signal), kept at unit RMS, mildly smoothed (`--lambda-smooth`).

Frames are treated as slices of one problem (own Cartesian mask or own radial spokes per frame,
`NUDFTOpBatched`), with per-frame low-res images (`--lambda-temporal` couples them). Stage 1 fits
the static model to all frames, stage 2 the dynamic one. Outputs: `maps_dynamic.npy` (T×N×H×W),
`alpha.npy`, `dynamic_modes.png` (modes + per-frame data loss static vs dynamic), `dynamic_map_change.png`.
This is the COMPACT-maps idea (low-rank temporal kernels) with the smoothness prior replaced by physics.

### 6.4 Results of the extensions

**Folded FOV** (synthetic, 8 coils, object 1.35× wider than the FOV along the phase-encode axis,
`runs/fold_*`). Ground-truth error of the primary maps:

| model | calib. residual | subspace err | absolute err |
|---|---|---|---|
| single set (standard) | 0.043 | 0.127 | 71 % |
| low-res division | – | 0.100 | 56 % |
| **fold sets (C(r), C(r ± FOV))** | **0.0034** | **0.030** | **24 %** |

The single-set model can only lower its residual by bending the physics (Laplace residual 10×
higher). With fold sets the primary image is the unwrapped central object and the two extra sets
hold the wrapped-in parts (`set_images.png`); some cross-talk between the two sides remains,
since telling which side a fold came from relies only on coil-sensitivity differences.
Before the conductor mask and the contribution-scaled ridge, the extra sets latched onto the
near-singular field next to the conductors and the result was *worse* than single-set (80 %).

**Dynamic, moving coils** (synthetic: 40 frames, R=4 random Cartesian per frame, anterior loops
move ±0.12·FOV/2 with "respiration", lesion with contrast uptake; `runs/dyn_synth`):

| maps | per-frame calib. residual | subspace err | absolute err |
|---|---|---|---|
| static Biot–Savart | 0.0111 | 8.8e-3 | 16.6 % |
| **dynamic, rank 2** | **0.0021** | **7.2e-5** | **5.3 %** |

The first learned temporal mode correlates 0.993 with the true (unseen) coil motion, and the
per-frame residual becomes flat instead of oscillating with breathing (`dynamic_modes.png`).
With a temporal-smoothness weight 1000× larger (`runs/dyn_synth_oversmoothed`) the modes were
flattened (correlation 0.44) and the gain was much smaller (subspace 7.6e-4): keep
`--lambda-smooth` small relative to the data term.

**Many volumes** (8 fastMRI-format volumes written by `write_fake_fastmri`: 8/10/12/16 coils, randomly
rotated arrays, 6 slices each fitted jointly; `fit-dataset --mode shared --holdout 2`, `runs/dataset_shared`):
per-volume ground-truth error of the shared-trunk fits 4–9 % absolute, 1–4e-4 subspace, Laplace residual ≤ 0.008.
Held-out test, 200 PINN iterations from the same wire init: scratch vs pretrained trunk 3.9 % vs 4.1 % and
4.6 % vs 4.9 % absolute error — **no benefit**. Expected here: the ground truth is an exact wire field,
so there is no systematic correction for the trunk to learn. Whether a learned prior helps on real
fastMRI (where real coils deviate systematically from single loops) is untested.

**Real dynamic data: GRASP free-breathing DCE liver** (`ismrm2016/grasp`, 6 coils, 2100 golden-angle
spokes binned as 21 spokes × 100 frames as in BART's recon script, BART trajectory verified by data
consistency: 0.164 vs 0.72 for shuffled spokes). Mean per-frame calibration residual:

| dynamic model | static | dynamic | map change over time | conductor motion |
|---|---|---|---|---|
| wires + fields, temporal image coupling 0.1 | 0.0133 | 0.0108 | 54 % | unbounded |
| wires only, no image coupling | 0.0131 | 0.0114 | 47 % | ~11 cm (implausible) |
| wires only, motion ≤ 15 mm | 0.0137 | 0.0114 | 34 % | 15 mm (at the bound) |

**Negative result.** In every variant the learned temporal modes follow the **contrast-agent bolus**
(frames ≈ 10–20), not breathing: object dynamics leak into the coil maps. At 21 spokes/frame each
frame spans several seconds, so respiration is averaged out, and a centimetre of conductor motion
near the body changes the near field enough to mimic regional enhancement — the physics prior
alone cannot separate the two. For DCE use static maps, or respiratory-resolved binning with modes
initialised from a respiratory self-gating signal; check `dynamic_modes.png` before trusting
dynamic maps.


## 7. Method comparison (evaluation framework)

`bspinn/methods.py` wraps eight estimators behind one interface: low-res division, Walsh, Inati,
ESPIRiT (BART `ecalib -m1`), NLINV (BART `ncalib`), Biot–Savart PINN, Biot–Savart wires, and the
no-physics ablation. A ground-truth oracle is added on synthetic data. `bspinn/evaluation.py`
holds the metrics; `scripts/evaluate_methods.py`, `summarize_eval.py` and `build_eval_report.py`
run the comparison and build the interactive report (`runs/eval/report/index.html`).

```
python scripts/prepare_eval_data.py --knee <bart-workshop kspace_fs> --brain <pics-brain/ksp>
BART=/path/to/bart ./run_eval.sh                      # ~3 h on 2 CPU cores, maps cached per method
python scripts/summarize_eval.py --eval runs/eval     # all_metrics.csv, summary.json, figures
python scripts/build_eval_report.py --eval runs/eval --findings runs/eval/findings.json
```

**Protocol.** All data are pre-whitened, so noise floors are exact. On the knee and synthetic
cases every estimator gets the same ACS block and nothing else. The prospective brain uses each
method's natural input.

**Metrics.**

| group | metric | what it measures |
|---|---|---|
| combine → expand | residual / noise floor, outside and inside the ACS, radial profile, per coil | coil images are combined with the maps (per-pixel LS), re-expanded and compared with the acquired k-space. The floor is the residual of pure noise through the same operator (Monte Carlo), so 1 = as good as the true maps. Outside the ACS is held out; inside, values < 1 mean the maps absorbed noise |
| reference image | SNR efficiency (mean, 5th pct), NRMSE/SSIM/PSNR vs truth or RSS, bias-free absolute combination | noise-debiased \|ĉᴴi\|/‖i‖ = fraction of the optimal combined SNR |
| parallel imaging | CG-SENSE at R = 2–6 (uniform + ACS), as delivered and with a common support; image NRMSE/SSIM/PSNR; missing-k-space NRMSE; acquired-sample NRMSE; analytic g-factor | unfolding quality and noise amplification |
| prospective | held-out k-space NRMSE (2 folds × 20 %), noise floor | brain, where no reference exists |
| maps | subspace, relative-phase, magnitude and absolute error vs truth; vortices; projector roughness; coverage; runtime | |
| reference-free (`bspinn/refree.py`) | see below | k-space only, no ground truth; noise fitting does not pay off |

**Reference-free metrics** (block `reference_free` per method in `results.json`; headline numbers in
`<out>/<case>/reference_free.tsv`). Lower is better for every headline number; the true maps give
the "ideal" column.

| headline | ideal | what it measures |
|---|---|---|
| `lco_outside_acs_over_floor` | 1 | leave-coil-out: coil j predicted from the other N−1 coils with the maps (x₋ⱼ = Σᵢ≠ⱼ Cᵢ* Iᵢ / Σᵢ≠ⱼ\|Cᵢ\|², rⱼ = Iⱼ − Cⱼx₋ⱼ), k-space residual outside the ACS over its Monte-Carlo noise floor. Coil j's noise is independent of its prediction. Tests relative magnitude and phase between coils, which is what SENSE uses. Also: worst coil, image-domain residual in the object. Prospective data: CG-SENSE from the other coils, over the noise propagated by the same (converged) reconstruction, and over σ² |
| `residual_signal_slope` | 0 | combine → expand residual / floor in 5 signal-level bins in the object: log-log slope vs signal power. Noise is signal-independent; map error scales with the signal |
| `residual_whiteness` | 1 | low-pass (Gaussian 2 px) energy fraction of the residual, relative to that of pure noise through the same operator; > 1 = spatially coherent residual = map error |
| `projector_hf_fraction` | ≈ 0 | spectrum of the per-pixel projector ccᴴ (gauge-invariant) on a tapered object mask: energy fraction outside the calibration band |
| `r2r_optimism` (`--resample r2r`) | ≈ 0 | recorrupted-to-recorrupted: y₁ = y + αz, y₂ = y − z/α have independent noise. Maps re-estimated from y₁; unexplained signal fraction (residual − noise floor)/signal on y₂ minus on y₁ (v30; v29 subtracted the over-floor ratios, which depend on the copies' different noise levels and came out negative). Also `r2r_independent_excess_rel` (unexplained signal fraction on y₂) and leave-coil-out on y₂ |
| `ssim_expand`, `ssim_expand_outside_acs`, `ssim_leave_coil_out` (+ worst coil) | higher, < 1 | SSIM of the magnitude coil images after expansion (C_j m; the same high-passed to k-space outside the ACS; the leave-coil-out prediction C_j x₋ⱼ) vs the measured coil images, in the object, weighted by coil energy. The reference is noisy, so the true maps stay below 1 and the ceiling depends on SNR: compare methods within a case. SSIM against noisy data mildly rewards smooth maps (on synthetic data low-res maps can edge out the true maps on the high-passed variant) |
| `sure_over_oracle`, `sure_map_dof` (`--resample sure`) | 1, 0 | Stein's unbiased risk of the combine → expand prediction, with the divergence of the maps w.r.t. the calibration data by antithetic finite differences (2 × probes re-estimations); over the risk of perfect fixed maps (σ² × #sampled; v30, v29 used the method's own non-zero support, inflating ESPIRiT). `sure_map_dof` = degrees of freedom the maps spend on calibration noise |

**Your own data.** `--loader MODULE:FUNCTION --base-folder ... --n N` (or `--indices`) adds N dataset
items as fully sampled 2-D cases: middle slice of a volume, whitened with a noise covariance estimated
from the k-space periphery and from the image background (the smaller is used, both are biased up by
signal; a warning is printed when they disagree by > 1.5x; `--noise-npy` overrides), central `--acs`
box, PE axis from partial-Fourier zeros. Default methods there: lowres, walsh, inati, espirit,
nlinv (BART; skipped if `$BART` is unset) and `pinn_api` (= `estimate_maps` as a user calls it, with
plane search and fold-over handling; `--device cuda`, `--pinn-quality`). `--cases synth` = every
synthetic case. `<out>/summary.tsv` has one row per case x method, `<out>/ranks.tsv` the mean rank
per method and metric, separately for synthetic and real cases.

```
python scripts/evaluate_methods.py --cases synth --loader dataloader_v2:get_dataloader \
    --base-folder /path/to/data --n 10 --device cuda --Rs 4 --out runs/eval_local
```

Only R2R and SURE are noise-proof when an estimator sees every sample (joint calibration, `brain8`);
the leave-coil-out and residual metrics are noise-proof outside the data the maps were fitted to.
SURE needs a deterministic estimator (fixed seed; GPU training jitter is divided by 2εσ):
`--sure-eps` (×σ, default 0.1) and `--sure-probes` trade bias for variance. The resample metrics
re-run every estimator 1 (r2r) or 2 × probes (sure) times per case.

Conclusions:

* When the coils obey Biot–Savart, the physics prior gives the most accurate maps by 1–2 orders of
  magnitude, and it is the only method at the noise floor at every SNR. At low SNR the hard wire
  model is better still.
* When they do not (per-coil non-harmonic factors), the PINN falls back to low-res-division
  accuracy and NLINV/ESPIRiT win. The wire-only model is worst there.
* On the real knee, NLINV and the PINN tie on every data-consistency metric. The Biot–Savart maps give
  11–20 % lower SENSE error when used as delivered, because they extrapolate physically outside
  the object. With a common support mask that advantage disappears.
* ESPIRiT (default crop) fails where the knee is cut by the readout FOV (5th-percentile SNR efficiency 32 %).
* Brain: the PINN ties ESPIRiT on held-out error (0.416 vs 0.415; v7 led with 0.409), using more
  samples (48×48 vs a 20×20 ACS). See "v7 → v8" below.
* Metric validity (Spearman vs ground truth, synthetic): the out-of-ACS residual tracks map
  error (0.66–0.97). The in-ACS residual does not, because methods fit noise there. SENSE error with maps as
  delivered is misleading: the true maps give 0.122 at R = 4, ESPIRiT 0.082. Use the
  common-support variant.
* Cost: PINN 12–53 min per slice on one CPU core, wires 1–10 min, the classical methods < 30 s.

**v7 → v8 (conductor fixes, §3 items 7–9).** Same benchmark, baseline maps reused, every fitted
method refitted. Unchanged within run-to-run noise: all synthetic 2-D cases, the knee at every ACS
size (residual 1.030 → 1.029), the model-size sweep. Better: 3-D synthetic (PINN 5.8e-5 → 4.0e-5,

(which now also gets the air Laplace penalty). Brain ablation (`scripts/brain_ablation.py`, deterministic; v8 default reproduces 0.4157 exactly):

(C·m on h×w), which ignores the truncation of the calibration data. The new default,

## 8. 3-D encoding

`bspinn/volume.py` runs the same method on 3-D Cartesian k-space (N, D, H, W):

* **Data and geometry.** `VolumeData`/`load_volume` (BART `.cfl` X,Y,Z,COIL or `.npz`), and `VolumeGeometry`
  (voxel size, and the physical axis of each array axis; B0 = z). Pre-whitening with a noise scan
  models the physical coils plus the known mixing, as in 2-D.
* **Problem.** `Problem3D` has a 3-D calibration block, the 2× oversampled model grid (the
  calibration k-space is predicted as the centre of the 3-D FFT of C·m), and the same wire/PINN
  training loops as 2-D (`fit_wires`, `fit_pinn`). The Laplace penalty uses collocation points
  throughout the imaged volume, not a slab around one slice. In 3-D the constraint therefore binds
  in every direction, and `--field-mode complex` becomes a meaningful relaxation (on one 2-D slice it constrains almost nothing).
* **Speed.** The wire field is exact on the calibration grid. The PINN correction is evaluated on a
  coarse grid (`--correction-grid 12`) and trilinearly upsampled during training (relative error < 5 %
  of the correction at 8³ in the unit test; the correction is smooth by construction). Final maps
  evaluate the network exactly at every voxel.
* **Unknown orientation.** `--axes auto` fits short wire models with B0 along each array axis and
  keeps the best (`select_orientation`; the unit test recovers the true axis from a wrong guess).

* BART's simulated head-coil maps are far from harmonic: the relative Laplacian of the ground truth
  is 10.4, against 0.03 for Biot–Savart truth and 3.3 for the mismatch case. There the physics prior is the wrong
  prior, and NLINV is clearly best. Real coils are harmonic only in the quasi-static limit. A rough
  estimate of the wave term, |ΔB|/|B| ≈ k² in the same units, gives about 2–3 at 1.5 T and about 6 at 3 T for a head.

  webinar data are 2-D, multi-slice or dynamic). Validating on real 3-D data is the main open item.
* SNR caveat: these 3-D cases normalise the maps over the whole grid, including points close to the coils, so the
  object is at a low SNR (median RSS signal about 3× the noise). The rankings hold, but the absolute errors are noise-limited.
* Cost: about 15–18 min per 48³ volume on one CPU core for the PINN, against about 0.3–2 min for ESPIRiT and NLINV.

### 8.1 Wave-aware physics (`--physics helmholtz`, 3-D)

The quasi-static model ignores the tissue's displacement and conduction currents. Those currents
leave div B = 0 intact but make curl B non-zero, and the field then follows
∇²B + k²B = 0 with complex k² = ω²μ₀ε₀ε_r − iωμ₀σ (homogeneous tissue). `--physics helmholtz` is the level-1
extension, with one complex k² for the object:

* **Full-wave wires** (`WaveWireLoopCoils`). Each current element radiates with the Green's function of
  the medium, dB = (1 + ikR) e^{−ikR} (dl × R)/R³, so the wire field solves the vector Helmholtz equation
  exactly and is divergence-free. It is computed as closed-form Biot–Savart, plus a closed-form k²/(2R)
  term, plus a Gauss–Legendre quadrature of the bounded remainder. The remainder is evaluated on the coarse
  correction grid during training and at evaluation, so the two are identical. k² = 0 gives exactly the quasi-static model.
* **Vector correction** (`HelmholtzPINN`). The network outputs the complex 3-vector correction B_c directly,
  so no derivatives are needed for the maps. The physics penalty is ∇²B_c + k²B_c = 0 and div B_c = 0 inside the
  object, with the same k² as the wires.
* **k²** starts from a tissue prior (`--b0-tesla`, `--eps-r`, `--sigma`) and is learned (`--learn-k2`). The
  report converts the fitted k² back to an equivalent homogeneous ε_r and σ.
* **3-D only.** On one slice the ∂²/∂z² term is unobserved; `validate` refuses `--physics helmholtz` outside `fit3d`.

```
python -m bspinn.cli fit3d data.cfl --out runs/vol --calib 12 --physics helmholtz --b0-tesla 3 --eps-r 60 --sigma 0.5
```

**Ground truth for testing** (`wave_loop_fields`): the same loop array, each loop replaced by its
equivalent magnetic-dipole sheet, with every dipole field an exact time-harmonic Maxwell solution in a
homogeneous lossy medium. This verifies to 1e-6 (Helmholtz residual) and 1e-5 (divergence) by finite
differences, and gives Biot–Savart at k = 0. Coils and object sit in one medium, which exaggerates wave
effects relative to coils in air beside a body: relative Laplacian of the maps 4.1 (1.5 T) and 10.1
(3 T), against 0.03 for quasi-static maps and 10.4 for BART's simulated coils.

**Results** (48³, ACS 12³, 600 + 600 iterations, single run; `runs/eval3d/wave15`, `runs/eval3d/wave3`; report section "3-D encoding"):

* With wave effects the quasi-static model breaks down at 3 T (map error 0.1). The Helmholtz model
  is 10× (3 T) to 46× (1.5 T) more accurate than ESPIRiT. Its residual and SENSE error are at the level of the true maps.
* k² is only loosely identified. Starting from a generic prior (ε_r 60, σ 0.5 S/m), the fit gives ε_r 84 / σ 0.49
  at 1.5 T (true 70 / 0.5) and ε_r 60 / σ 0.53 at 3 T (true 50 / 0.6). The maps are as good as with the
  true k² (3.1e-4 vs 3.2e-4): the correction absorbs the rest. Treat the fitted ε_r and σ as nuisance
  parameters, not as tissue property estimates.
* Limits of this test: the medium surrounds the coils and is homogeneous, the coils are ideal loops, and the
  ground truth comes from the same family of physics as the model. Next would be heterogeneous tissue (piecewise
  k², level 2), coils in air beside a body (a volume-integral or FDTD reference), and real 3 T or 7 T 3-D data.
* Cost: about 42 min per 48³ volume on one CPU core (the Laplace PINN takes about 16 min).

**How many iterations?** `scripts/accuracy_sweep.py` measures, on your own (preferably fully sampled)
data and without ground truth, the k-space residual over the noise floor, the CG-SENSE error at R = 4,
the map change relative to the longest budget and the seed-to-seed spread, for iteration budgets from
half of `fast` to twice `default`. `scripts/hyper_sweep.py` searches the optimiser and regularisation
settings (Adam betas, learning rates and schedule, collocation batch, loss weights, network size) for
the fastest convergence at unchanged quality: one knob at a time, greedy combination, then the budget at
which the combination matches the current `default` preset. New FitConfig fields for it: `adam_beta1`,
`adam_beta2`, `lr_schedule` (cosine | linear | constant), `lr_warmup`, `lr_min_wires`, `lr_min_pinn`,
`lr_image_wires`, `lr_image_pinn` (defaults reproduce the previous behaviour).

**Fold-over (object wider than the FOV).** Tissue beyond one phase-encode edge appears at the opposite
edge and is seen there by the coils on the far side. Physical maps are not periodic (ESPIRiT/NLINV maps are,
by construction), so without correction that band gets the wrong coils and undersampled SENSE shows
stripes. `estimate_maps(fold="auto")` (default, 2-D) compares the calibration coil images with the maps and
with the maps shifted by one FOV along each phase-encode axis (the readout axis is skipped when a mask shows
it); in edge-connected regions where the shifted set explains the coils much better, the returned maps
are the effective sensitivity m1·C + m2·C(r ± FOV). `info["fold"]` lists the corrected regions. On a
fastMRI knee slice with the thigh wrapping into the opposite edge (vd mask, R = 4) this removed the
stripes (column-stripe index 0.43 → 0.09, as low as with low-resolution maps); synthetic wrap test:
SENSE NRMSE 0.46 → 0.27.

Two guards (v31). The readout axis is never searched: `estimate_maps` infers it from `mask` (the axis
along which every acquired line is fully sampled) or takes `readout_axis=`; a mask that is only a
calibration box cannot show it, which is what the benchmark passed, so `pinn_api` now hands it over.
And the shifted maps are evaluated one FOV away, where conductors may legitimately sit (outside the
object): pixels where they are rougher than 3x the 99th percentile of the maps' own gauge-free
roughness (a conductor's near field) are never used. On item 19870 of the dataloader run (15-channel
knee cut by the FOV along the readout) the PINN maps carried exactly such a near field inside the leg:
leave-coil-out 1.85x the floor, SENSE R4 error 0.194 vs 0.075 for NLINV.

**In-plane B0 orientation (v32).** That diagnosis was wrong: item 19870 failed because the plane search
picked `coronal_t` (B0 along the columns) for a coronal knee (B0 along the rows). The probe losses were
within 15 % (0.133 vs 0.150), and the wrong orientation fits the calibration data *better* in full
fits (data loss 0.0114 vs 0.0140) while extrapolating much worse (SENSE R4 0.143 vs 0.083,
leave-coil-out worst coil 3.6 vs 1.5 x floor; the benchmark's own maps match the `coronal_t` fit
4x more closely than the `coronal` one). Held-out prediction of acquired samples outside the calibration
box separates them (0.47 vs 0.37 relative error). So, when the in-plane orientation is ambiguous and
such samples exist, `estimate_maps` now fits both orientations and keeps the one with the lower held-out
error (`plane_select='heldout'`, default; `'probe'` = old behaviour; costs a second fit only in that
case). With only a calibration box (the benchmark protocol) there is nothing to hold out: pass
`plane=` (benchmark: `--pinn-plane coronal` for coronal knees).

**Noise amplification of different maps:** `scripts/gfactor_compare.py` reconstructs the same
retrospectively undersampled data with each set of maps (identical CG-SENSE, λ, iterations) and reports
the pseudo-replica g-factor (mean / median / 95th percentile in the object) and the error against the fully
sampled combination. Knee slice of §7, R = 4, 24 ACS lines: mean g 1.70 (ESPIRiT), 1.87 (NLINV),
1.91 (Biot–Savart PINN), 1.86 (wires); NRMSE 0.112 / 0.122 / 0.130 / 0.120.

Tips: the cost scales with the calibration grid and the number of coils, not with the image matrix
(except `solve_image`). Being launch-bound, a GPU iteration costs about the same for many more
collocation points (`n_colloc`) or a larger calibration grid: use them. `joint_maps="exact"` is the
reference for the hybrid maps; `"interp"` is the cheapest and slightly biased.

### 8.3 Closing the gap to NLINV on real data (v33)

`scripts/method_lab.py` fits one variant on a fixed panel and scores it with k-space-only metrics
(ACS-only protocol, pre-whitened data, B0 orientation given, `quality='fast'`, CPU): item 19870 (fastMRI
coronal knee, 15 ch), the BART-workshop knee, three held-out slices never used for tuning (two axial knees,
one 12-channel Calgary-Campinas brain), a prospective fold-over knee, and the synthetic phantoms.

**Diagnosis.** (1) A self-consistency test (the real knee anatomy times the PINN's own maps, i.e. data the
model represents exactly) still left the combine->expand residual in the ACS at 75x the noise floor and a
1.3 % subspace error: part of the gap is the optimisation, not the physics (more iterations, a 4x learning
rate or an L-BFGS polish all help; finer calibration grids, weaker norm/image penalties do not). (2) The
PINN/NLINV map ratio on the knee is 82 % explained by a smooth (Fourier order 2) per-coil complex factor:
the model misses smooth per-coil deviations. (3) Real receive channels are complex mixtures of the elements
(residual coupling, preamplifier decoupling), which one real quasi-static field per channel with a global
phase cannot represent.

**Changes** (both on by default for 2-D `estimate_maps`; off: `learn_mixing=False, resid_order=0`):
* `learn_mixing`: channels = (I + E) x element maps, E complex off-diagonal, ridge `lambda_mix`
  (`models.ChannelMixer`), learnt in the PINN stage (from the wire stage on, `'all'`, was worse).
* `resid_order=3`: every map times exp(u_j), u_j a complex 2-D Fourier series of order 3 over the FOV with a
  Sobolev ridge `lambda_resid` (`models.SmoothFactor`); constant beyond the FOV.
* optional `iters_polish=N`: full-batch L-BFGS of all parameters after the PINN stage.
* `optimizer=` (`--optimizer` on the command line): `'adam'`; `'lbfgs'`: every stage (handedness /
  orientation probes, wires, PINN, joint full-resolution, dynamic) is minimised by full-batch L-BFGS with a
  strong-Wolfe line search on a fixed collocation set, and `iters_*` count L-BFGS iterations (in the joint
  stage: L-BFGS on the maps for the current image, then CG on the image, alternating every `lbfgs_inner`
  iterations); `'adam+lbfgs'`: the Adam stages, then the L-BFGS polish (`iters_polish`, default 200). Since v42 `'adam+lbfgs'` is the `estimate_maps` default for 2-D PINN fits (§8.6); the
  `FitConfig` / CLI default stays `'adam'`.

### 8.4 Automatic SENSE regularisation (`sense_lambda="auto"`, v36-v37)

The Tikhonov weight of the returned image is chosen from the data by default (`bspinn/senselam.py`); a
number still sets it by hand, `sense_lambda_scale` multiplies an automatic value, and the choice and every
rule's diagnostics are in `info['sense_lambda']`.

`'auto'` = `'auto-cv+map'`: k-space cross-validation, floored by a noise-based value. Withhold 10 % of the
acquired phase-encode lines outside the calibration box (2 folds), reconstruct from the rest on a log grid
(1e-5..1, 16 values, batched CG on the device), predict the withheld lines (up to one global scale per
lambda) and keep the best; then take max(that, sigma^2 / s^2), the Gaussian-MAP (Wiener) weight from the
noise variance (outer k-space) and the mean signal power. Withholding whole lines makes the reconstruction
unfold them, so the criterion sees noise amplification and residual aliasing / map errors alike; the
floor catches the rare collapses of cross-validation to tiny weights. Also available: `'auto-cv'`,
`'auto-map'`, `'auto-gcv'`, `'auto-discrepancy'`. With `solve_image=True` and an automatic weight the joint
stage keeps `lambda_joint_img` (1e-2) for the maps; the returned image is recomputed with the chosen weight.

`scripts/sense_lambda_eval.py` on 20 slices of your dataset (fastMRI knee and brain, Calgary-Campinas;
4-22 coils; R=4 variable density, ACS 24; maps by `estimate_maps`, GPU; ~5 s per slice for the choice).
NRMSE against the fully sampled image combined with the same maps, relative to the best weight of a
21-point grid (the oracle weight itself ranged 3e-3 .. 1):

| **auto (cv + map floor)** | **1.007** | **1.014** | **1.042** | **1.062** | **95 %** |
| cv | 1.011 | 1.046 | 1.072 | 1.469 | 85 % |
| gcv | 1.026 | 1.119 | 1.377 | 1.470 | 55 % |

### 8.5 True joint fitting (v39)

`solve_image=True` used to be sequential in two ways: the maps were first fitted to the calibration data
alone, and with `sense_lambda='auto'` (v36-v38) the returned image was recomputed after the joint stage.
Now:
* the automatic image weight is chosen once at the start of the joint stage (from the calibration maps)
  and used inside it; the returned image is the joint solution (`info['sense_lambda']`);
* `joint_start='wires'`: the wire model is still initialised on the calibration data, but the PINN stage
  is replaced by the joint stage, so the maps (network, wires, coupling, smooth factor) and the
  full-resolution image are fitted together on all acquired k-space from the first PINN step
  (iters_pinn + iters_joint iterations);
* `joint_image='gradient'`: the image is a parameter of the same optimiser as the maps (simultaneous
  steps; with `optimizer='lbfgs'` one quasi-Newton problem in maps and image) instead of an exact
  CG-SENSE solve after every map step (`'cg'`, default). The final image is the exact CG solution for the
  final maps either way.

On a 96x96 8-coil Biot–Savart phantom (R=4) all variants give the same image (NRMSE 0.1881-0.1888) and
map error within 2x (2.0e-5 calibration only, 2.4e-5 joint/gradient, 2.8e-5 joint/CG, 4.0e-5 joint from the
start/CG): the physics model leaves little for the joint fit to add there. Real data: run
`scripts/joint_eval.py` (variants calib_only, joint_cg, joint_grad, joint_start_cg, joint_start_grad,
`*_lbfgs`; image vs fully sampled RSS, map leave-coil-out). Defaults unchanged until that is measured.

### 8.7 Image prior: zero-shot self-supervised reconstruction (ZS-SSL)

The error budget of v42 (README §8.6 slices k19870, val_outlier and the self-consistency case) puts the
remaining R = 4 image error in the reconstruction, not in the maps: CG-SENSE with PINN vs NLINV maps differs
by ~1 % NRMSE, and even exact maps leave 0.03-0.05 noise-free NRMSE (Tikhonov bias + g-factor noise).
`scripts/zs_ssl.py` replaces the Tikhonov prior by ZS-SSL (Yaman et al., ICLR 2022,
https://arxiv.org/abs/2102.07737): an unrolled network (ResNet denoiser, 15 blocks x 64 channels, CG data
consistency, 10 unrolls, shared weights) trained per scan on its own acquired samples only. Omega is split
into Gamma (20 %, early stopping) and K = 50 Theta / Lambda splits (rho = 0.4, Gaussian selection, centre
kept); loss: normalised l1-l2 on the Lambda k-space. The maps are any estimator's, by default read from the
cache of an `evaluate_methods.py --joint` run, so the slices, masks and maps are those of §8.6. Optional
`--pretrain-n N`: self-supervised (SSDU) pretraining on N other items of the dataset, then zero-shot
fine-tuning per slice (ZS-SSL-TL). Fully sampled data is only used to score.

```
# 3 slices first, to time it (~0.3-0.5 s per step on a recent GPU at 320x368x15, 50 steps per epoch)
python scripts/zs_ssl.py --loader dataloader_v2:get_dataloader --base-folder ... --n 20 --indices <3 of them> \
    --R 4 --maps pinn_api nlinv --maps-cache runs/eval_joint --device cuda --amp --out runs/zs_ssl
# all 20 (resume-safe), then: pretraining + short fine-tuning
python scripts/zs_ssl.py ... --n 20 --maps pinn_api nlinv --maps-cache runs/eval_joint --device cuda --amp --out runs/zs_ssl
python scripts/zs_ssl.py ... --n 20 --maps pinn_api --maps-cache runs/eval_joint --pretrain-n 200 \
    --pretrain-steps 20000 --finetune-epochs 10 --device cuda --amp --out runs/zs_ssl_tl
```

Reported per (slice, maps): `cg_auto` (CG-SENSE, automatic lambda, same maps), `zs`, and with pretraining
`tl0` (pretrained network, no fine-tuning); NRMSE / SSIM / PSNR vs the fully sampled RSS inside the object.
The reference is noisy, so a denoising reconstruction is slightly penalised on low-SNR slices. CPU check
(synth8_noisehi, tiny network: 4 unrolls, 4 blocks x 24 channels, 40 epochs): SSIM 0.689 -> 0.784,
PSNR 25.1 -> 26.3 dB against CG-SENSE with the same (true) maps.

### 8.8 Training the reconstruction network on the whole dataset

`scripts/train_recon.py` trains the same unrolled network (zs_ssl.py) on every item of the dataloader, with
a new random mask per sample (R ~ U[2, 8], vd / random / uniform lines, 16 / 24 / 32 calibration lines,
along the item's phase-encode axis), so that one network serves any mask. Maps during training: a fast
estimator from that mask's calibration region (Inati by default, in the data workers), or a per-item cache
of any estimator (`--precompute-maps pinn_api --shard k/n`, then `--train-maps cache:pinn_api`; the training
calibration size is then fixed to `--maps-acs`). Loss `supervised` (fully sampled SENSE-1 image with the same
maps) or `ssdu` (acquired samples only). The 20 evaluation items of §8.6 (same --n / --pick-seed) and every
index within `--exclude-window` (300) of them are never trained on; `--val-n` validation items (fixed R = 4
masks) pick `best.pt`. Training resumes from `last.pt`. `--eval` scores CG-SENSE vs the network (and
optionally per-slice ZS-SSL fine-tuning, `--zs-epochs 0 10`) at `--eval-R` with `--eval-maps` (PINN / NLINV
maps from the `evaluate_methods.py --joint` cache).

### 8.9 Image priors with the estimated maps: TV, wavelets, a trained network

`bspinn/prior.py` replaces the Tikhonov term of the image reconstruction (maps fixed) by isotropic total
variation, orthonormal Daubechies wavelets (db4, 4 levels, coarsest band free) or both:
x = argmin 1/2 ||M F C x - y||^2 + beta TV(x) + ratio beta ||W x||_1, by ADMM (warm-started CG image steps,
closed-form shrinkage), batched over a grid of weights. The weight is chosen like the SENSE lambda, by
k-space cross-validation on withheld phase-encode lines (`senselam.cv_masks`, scale-invariant held-out
error) and `prior.select_weight` (v46, calibrated on the 20-slice GPU run below):
* flat CV curve (max / min < 1.04, `FLAT_CV`): held-out k-space is noise-dominated, the largest grid weight;
* otherwise the lowest INTERIOR local minimum, refined by a parabola in log weight, x `AUTO_SCALE` = 0.35
  (the folds withhold 10 % of the lines, a harder problem that wants more regularisation); minima at the
  grid edges are ignored: the lowest-weight edge was a spurious global minimum in 20 % of the cases
  (1.2-3x the oracle NRMSE with the plain argmin);
* no interior minimum (6 of 240 cases): `FALLBACK_WEIGHT` = 2e-3.

C, img, info = estimate_maps(ksp, "2d", mask=mask, solve_image=True, image_prior="tv+wavelet")   # weight 'auto'

img = sense_image(ksp, C, "2d", mask=mask, prior="net:runs/recon/best.pt")    # network of §8.8 as the prior
```

### 8.10 Higher-order smooth factor (continuation) and the prior inside the joint fit (v48)

**Smooth factor.** The investigation of v42 showed that the PINN's remaining calibration-region residual is
smooth, coil-specific structure at a 2-3 cm scale (Fourier orders 4-8 over the FOV) that the order-3 factor
cannot carry. `resid_order_final=8` (new `estimate_maps` 2-D default) raises the factor after the PINN stage
(`SmoothFactor.grown`: same values, new coefficients 0) for the polish and joint stages, with the penalty
(1 + |k|^2 / `resid_k0`^2)^`resid_sobolev` (3, 2) and ridge `lambda_resid` (`lambda_resid_final` to change it).
The PINN stage keeps order 3, so the physics carries the large-scale field first. Calibration-only fits, quality
fast:

| case | variant | ACS c->e / floor | lco / floor (held out) | worst coil | SENSE R4 | gt subspace error |
|---|---|---|---|---|---|---|
| k19870 (knee) | v47 (order 3) | 29.6 | 1.0469 | 1.225 | 0.0771 | |
| | order 3 -> 8 | 17.4 | 1.0259 | 1.174 | 0.0757 | |
| | order 3 -> 8, ridge 1e-4 | 16.0 | 1.0213 | 1.156 | 0.0753 | |
| val_cc (brain) | v47 / ->8 / ->8 ridge 1e-4 | 2.15 / 1.61 / 1.52 | 1.0361 / 1.0355 / 1.0353 | 1.075 | 0.0984 | |
| synth8 (exact Biot-Savart) | v47 / ->8 / ->8 ridge 1e-4 | 0.94 / 0.90 / 0.87 | 0.997 / 1.000 / 0.998 | 1.05 | 0.0717 | 3.5e-5 / 1.0e-4 / 1.7e-4 |

NLINV on k19870: lco 1.019. Two real slices: confirm on 20 (below). `resid_order_final=0` restores v47.

**Prior inside the joint fit.** With `solve_image=True` and `image_prior='tv'` (or another built-in prior) the
joint stage now updates its image with the prior: after every map step a few warm-started ADMM iterations
(`joint_prior_admm`, default 3; splits and duals persist across steps), the weight chosen once by k-space
cross-validation with the calibration maps (the same rule as §8.9). The maps are then refined against a
denoised image instead of a noisy Tikhonov one. `joint_prior=None` keeps the Tikhonov image inside the fit.
FitConfig: `joint_prior`, `joint_prior_weight`, `joint_prior_admm`, `joint_prior_options`; `info['joint_prior']`.

### 8.11 Dynamic (cine) imaging: OCMR, GRO undersampling, time-averaged vs per-dynamic maps

`scripts/ocmr_eval.py` evaluates on OCMR fully sampled 2-D cine (https://www.ocmr.info; ISMRMRD files, read by
`bspinn/ocmr.py`: noise scans for whitening, 2x readout oversampling removed, partial Fourier placed). For
R = 1 (fully sampled) and every --R, a GRO mask per frame (`masks.gro_mask` / `gro_lines`: golden-ratio offset
Cartesian sampling, Joshi, Ahmad et al., arXiv:2206.03630, s = 2.2, alpha = 3; no per-frame calibration
region, the time average covers every line). Maps:

| maps | from |
|---|---|
| espirit, nlinv | BART ecalib / ncalib on the time-averaged k-space (one map set for all frames) |
| pinn_avg | `estimate_maps` 2-D on the time-averaged k-space |
| pinn_dyn | `estimate_maps(layout='dynamic', rank=2)`: per-frame maps (temporal modes of the coil array) from the undersampled frames |
| pinn_dyn0 | the same with rank 0: one static set fitted to all frames jointly |
| pinn_frame | independent 2-D fits per frame (optional, slow) |

Reconstructions: R = 1 SENSE-1 per frame (+ reference-free map metrics per frame); R > 1 per-frame CG-SENSE
(automatic Tikhonov from the middle frame) and spatio-temporal TV (`prior.dynamic_prior_image`: cyclic
temporal TV + 0.25 x spatial TV, ADMM, weight by k-space CV with withheld lines in every frame,
`select_weight` with `DYN_SCALE` = 1). Metrics vs the fully sampled per-frame RSS: NRMSE / SSIM / PSNR per
frame and `dyn_nrmse` (frame minus time average: temporal fidelity).

v50 fixes for the dynamic PINN: (1) the dynamic layout gets the 2-D model (channel coupling, smooth factor
3 -> 8, L-BFGS polish; `DynamicCoils` now applies the static model's factor and coupling to every frame);
(2) `dynamic_static='average'` (default): the static part is fitted to the time-averaged k-space and only
the temporal modes to the frames; the joint fit to GRO frames (no per-frame calibration region) was
ill-posed (subspace error 0.22 vs 0.045). `select_weight` also accepts an upper-edge CV minimum.

### 8.12 Phase poles and small calibration regions (Blumenthal & Uecker, arXiv 2508.04685)

Gauge (common-phase) poles: `bspinn.recon.gauge_poles` (per-coil winding numbers on 2x2 plaquettes and, by
Stokes, on loops of radius 6 -- NLINV's poles are spread over ~10 px), `remove_gauge_poles` (point-like poles;
exact: one unit-modulus factor for all coils). `phase_ref='inati'` falling back to the model phase (no usable
virtual body coil: 3 T, many coils) now removes the model phase's poles (`unwind=False`: v54).

OCMR (cine, Cartesian): ESPIRiT has gauge poles in every case, NLINV none, the PINN only at 3 T (model-phase
fallback). Swapping the gauge (pole removal, another method's gauge, NLINV into ESPIRiT's) changes neither
spatio-temporal TV nor 2-D TV (|dNRMSE| <= 2e-4 at three weights): SENSE / Tikhonov are gauge-invariant and TV
pays little for a vortex. The poles mark where maps are worse (leave-coil-out within 8 px of a pole: ESPIRiT 3.5-3.9,
NLINV 1.5-1.8, PINN 1.8-2.5) and matter for phase applications.

Brain MPRAGE planes of the paper (3 T, 20 -> 12 virtual coils, 2x2 + ACS 3 / 7 / 15): uncorrected `bart nlinv` has
a gauge pole in the head in 4 of 9 cases (with the dark 'black hole'), `--phase-pole 0` in none, and the
correction improves NLINV's image in 8 of 9. ACS 7, slice 189 (lco object / near pole, R=4 SENSE NRMSE): ESPIRiT
fails (kernel 5), NLINV 1.39 / 6.81, 0.109; NLINV corrected 1.21 / 1.15, 0.097; PINN (v54, maps only) 1.16 / 1.09,
0.093. ACS 3: PINN 9.8 vs NLINV corrected 2.1 -- an undersampled calibration box gives an aliased image whose
support is inflated (0.96 / 0.73 of the FOV at ACS 3 / 7 vs 0.42): v55 restricts it to the alias-free block's
(`init_from_acs`), and the joint stage (`solve_image=True`) uses all samples as NLINV does.

```
